# Studio control state survives rebuilds

The studio's control panels (`lib/controls.ts`, `hooks/use-control-panel.ts`, `lib/gauge-panels.ts`) are rebuilt whenever an input they depend on changes: the layer kind, the shape, the domain, or the range toggle. A user's edits must survive that, and survive strict mode's remounts.

- **Configs are memoised on their inputs.** Each panel config is a function of a few primitives (`gaugeConfig(kind, linear)`, `valueConfig(min, max, range)`, `arcsConfig(linear)`, `cutoffsConfig(min, max)`), and the panels that depend on nothing are built once. `useGaugeControllers` memoises them on those inputs, which it reads from the store with `useControlValue`. `ControlsStore.setPanel` ignores a config object it already holds, so a render that changes nothing doesn't reach the store.
- **Loading a layer is one pass.** `loadPanel` takes the values and the config built from those same values, so slider ranges and `from` are right before anything is normalised. Normalising a layer against the previous layer's config would clamp it, for example a 6,500 rpm value against a 0 to 100 slider.
- **Colour controls hold both fields.** A colour config (`_variant: "color"`) always holds `token` and `custom`, so a layer's custom hex lands in the same pass as its token. `resolveValues` leaves `custom` out while a palette token is picked, and `ControlsRoot` hides its picker.
- **Lenient normalisation.** `ControlsStore.setPanel`/`normalizeValue` keep existing values. Sliders are clamped and snapped. Selects fall back only when their option is gone. Values whose control has disappeared, such as a bar's `orientation` while the gauge is round, are kept. A transition keeps whichever shape (spring or easing) the user switched it to. As a result, the store can hold values that have no control at the moment.
- **Retained on unmount.** `unregisterPanel` moves values into `retained` and `setPanel` picks them up again, so strict mode's mount, unmount and remount, or hiding a panel, doesn't reset edits. Values for panels that never return stay in memory for the session.
- **Zones keep panel order.** `buildSpec` clamps each cutoff at or above the previous one and forces the last zone to `max`. Sorting the cutoffs would make colours jump between zones while a slider is dragged. A cutoff that's out of order collapses to an empty zone.
- **`toggle()` widens booleans.** Panel configs use `satisfies ControlConfig`, which keeps literal types, so a bare `show: true` would type as `true`. The identity `toggle(value): boolean` widens it.
- **Storage is best-effort and syncs within the tab.** `readStored`/`writeStored` swallow the errors browsers throw when storage is disabled or full, so a preference just doesn't persist. The `storage` event only reaches other tabs, so `subscribeStored` also keeps a local listener set that `writeStored` notifies.
